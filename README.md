# Спортивное программирование Оренбургской области

Платформа региональной федерации: публичный календарь, реестры и кабинеты пяти ролей, заявки, протоколы, рейтинги, сборная, документы и аналитика. Интерфейс на русском, светлое оформление по предоставленному референсу. Все данные seed вымышлены и помечены как демонстрационные.

## Стек и структура

- `apps/web` — Next.js App Router, React, TypeScript strict, Tailwind CSS, Lucide, React Hook Form + Zod, TanStack Table, Recharts. Общие UI-компоненты находятся в `src/components/ui.tsx`; диалоги используют нативный `dialog` с удержанием фокуса и Escape.
- `apps/api` — модульный монолит NestJS, REST, Swagger, class-validator, серверные сессии.
- `prisma` — PostgreSQL, Prisma, две SQL-миграции, демонстрационное заполнение.
- `packages/shared` — роли, дисциплины, начальные правила рейтинга и общие типы.
- ExcelJS, PDFKit с кириллическим DejaVu Sans, docxtemplater, QRCode — генерация документов из БД.

## Запуск всего проекта одной командой в Docker

Нужен только запущенный **Docker Desktop с Linux engine** (Docker Compose v2). Node.js, npm, локальный `node_modules` и предварительное создание `.env` не нужны. Из папки проекта выполните:

```powershell
docker compose up --build -d --wait
```

Открыть **http://localhost:3000**. API и Swagger доступны через тот же адрес: **http://localhost:3000/api/docs**. Для входа в кабинет федерации: `federation@fsp-orenburg.demo` / `Demo1234!` (полный список ниже).

Compose сначала проверяет готовность PostgreSQL, применяет миграции в одноразовом контейнере `init`, заполняет **только пустую** БД демонстрационными данными и запускает API и фронтенд. Завершённый `init` со статусом `Exited (0)` — нормальное состояние. Первый запуск дольше из-за скачивания и сборки; следующие используют кэш Docker. `.env` и локальные библиотеки не попадают в образы.

Данные сохраняются в томе `fsp_pg_data`. Используется тот же том, что и при прежнем запуске только PostgreSQL из этой папки: существующие записи не очищаются. `docker compose down` удаляет контейнеры, но сохраняет данные; не добавляйте `-v`, если хотите их сохранить.

```powershell
docker compose logs -f api web init  # Журнал приложений
docker compose stop                # Остановить с сохранением данных
docker compose up -d --wait        # Снова запустить без пересборки
```

Перед переходом с локального `npm start`/`npm run dev` остановите его через Ctrl+C, чтобы освободить порт 3000. API работает только во внутренней сети Docker; порт 4000 на хост не публикуется. PostgreSQL доступен только внутри Docker; локальный порт 5432 не требуется. Для разработки на хосте есть отдельный `docker-compose.dev.yml`.

Необязательные настройки `.env`: `WEB_PORT` (порт сайта), `DOCKER_PUBLIC_URL` (полный адрес сайта для проверки Origin и QR-ссылок), `POSTGRES_*`, `DOCKER_SEED_DEMO=false` (не добавлять демоданные), `SESSION_COOKIE_SECURE=true` (при размещении за HTTPS). При другом порте меняйте и адрес: например, `WEB_PORT=3001`, `DOCKER_PUBLIC_URL=http://localhost:3001`. Стандартный HTTP-запуск использует `SESSION_COOKIE_SECURE=false`; для внешнего HTTPS-размещения включите true, замените демодоступы и пароль БД. Изменение POSTGRES_PASSWORD в файле не меняет пароль уже существующей БД.

Dockerfile использует отдельные этапы сборки, миграций и запуска. Фронтенд упакован в Next.js standalone, API получает только свои runtime-зависимости и шрифты для PDF. Компиляторы и Prisma CLI не нужны работающему API. Локальный режим разработки остаётся доступен ниже.

## Запуск с нуля для разработки на хосте


Требования: Node.js **22.12+** (рекомендуется LTS), npm, Docker Desktop с запущенным Linux engine. Порты 3000, 4000 и 5432 должны быть свободны.

Команды выполняются из корня репозитория:

```powershell
Copy-Item .env.example .env
npm ci
docker compose -f docker-compose.yml -f docker-compose.dev.yml up -d postgres
npm run db:setup
npm run dev
```

В macOS/Linux вместо `Copy-Item` используйте `cp .env.example .env`. Если `.env` уже существует, сохраните свои настройки. `npm ci` генерирует Prisma Client и собирает общий пакет. `db:setup` применяет миграции и заполняет пустую БД; повторный запуск seed сохраняет существующих пользователей и данные. Для сервера разработки используется TypeScript compiler: он сохраняет необходимую NestJS metadata декораторов.

- Сайт: [localhost:3000](http://localhost:3000).
- API: [localhost:4000/api](http://localhost:4000/api/disciplines).
- Swagger: [localhost:4000/api/docs](http://localhost:4000/api/docs).

Раздельный запуск в двух терминалах:

```powershell
npm run dev:api
npm run dev:web
```

Проверка и запуск собранных приложений:

```powershell
npm run build
npm run start -w @fsp/api
# В другом терминале:
npm run start -w @fsp/web
```

Сборка Next.js не требует работающего API: данные загружаются при открытии страниц. API требует доступного PostgreSQL. В этом варианте команда `docker compose -f docker-compose.yml -f docker-compose.dev.yml up -d postgres` запускает только базу, а приложения запускаются на хосте. `Ctrl+C` останавливает dev-команду; `docker compose stop` останавливает БД с сохранением тома.

## Реализованные сценарии

- Публичная главная, календарь с поиском и фильтрами, карточка соревнования, шесть дисциплин, обезличенный рейтинг, проверка справки по QR.
- Вход, выход с отзывом сессии, ограничение попыток входа, несколько ролей, серверные проверки прав. Секрет сессии находится в HttpOnly cookie; в БД хранится SHA-256 хеш.
- Реестр спортсменов с поиском, пагинацией, сортировкой текущей страницы и созданием записи; карточки спортсменов, реестры тренеров и судей, организации и справочники.
- Создание и публикация соревнований, заявки спортсмена и тренера, модерация с причиной отказа, отзыв ожидающей заявки, судейские назначения.
- Проверки срока приёма, возраста на дату соревнования, дисциплины, активной тренерской связи и дисквалификации. Частичный уникальный индекс не допускает двух активных заявок.
- Ввод результатов только для одобренных заявок, ранжирование всех участников, равные места при равных баллах (1, 1, 3), публикация протокола. Исправление опубликованных результатов переводит протокол в черновик и пересчитывает рейтинг; требуется повторная публикация.
- Сезонный рейтинг по дисциплине, фильтры возраста и минимального разряда, расшифровка начислений, изменение базовых баллов и пересчёт. Коэффициент ×1,2 применяется один раз при двух и более призовых выступлениях.
- Создание составов сборной, рейтинговый и ручной отбор, исключение из состава, история изменений. Возраст проверяется на **31 декабря сезона** как явно выбранное правило MVP; это не утверждение о спортивном нормативе.
- Заявки на разряды и судейские категории. Даты действия и номер приказа вводит федерация. История сохраняется, истёкший разряд не отображается действующим.
- Запросы тренерской привязки, подтверждение/приостановка/завершение спортсменом; результаты подопечных.
- Антидопинговые записи и регистрация полученных согласий с версией текста и сведениями о представителе.
- PDF/XLSX протокола, PDF состава сборной, DOCX проекта приказа, PDF истории спортсмена, XLSX отчёта, PDF справки с криптографически случайным QR-токеном.
- Внутренние уведомления, контроль сроков разрядов, категорий и приёма заявок, журнал основных действий.
- Отчёты и графики по дисциплинам, организациям, муниципалитетам и возрасту. Динамика отражает накопленное число записей по году начала занятий; это **не исторический срез статусов** спортсменов.

## Проверка сквозного сценария вручную

1. Войти как федерация. В календаре создать соревнование по алгоритмическому программированию, выбрать подходящую возрастную группу. Открытие заявок — в прошлом, закрытие — в будущем до начала соревнования. Опубликовать.
2. Выйти и войти как `athlete@fsp-orenburg.demo`. Открыть календарь и подать заявку. Возраст вычисляется по дате рождения seed-профиля (12.04.2008).
3. Войти как федерация, одобрить заявку в разделе заявок или карточке соревнования. Ввести баллы, сохранить результаты и опубликовать протокол.
4. Проверить рейтинг и его расшифровку. Создать состав сборной по той же дисциплине и подходящей группе, добавить спортсмена, скачать список и проект приказа.
5. В кабинете спортсмена открыть результаты и документы, сформировать справку. Открыть ссылку из QR-кода и проверить подлинность.
6. Исправить результаты как федерация: публичные результаты скрываются до повторной публикации, начисления обновляются. Проверить журнал действий.

## Автоматические проверки

```powershell
npm run typecheck
npm test
npm run test:integration
npm run build
```

`test:integration` требует работающего PostgreSQL. Создаёт отдельную временную схему `fsp_test_<timestamp>`, применяет миграции, заполняет её, запускает тестовый API на 4100, проверяет HTTP-сценарии и содержимое PDF/XLSX/DOCX. В конце останавливает свой сервер и удаляет **только свою временную схему**. Основная схема не изменяется. Пользователю БД нужны права создания схем.

## Конфигурация и границы MVP

- `DATABASE_URL`, `API_PORT`, `WEB_ORIGIN`, `SESSION_TTL_HOURS`, `LOGIN_MAX_ATTEMPTS`, `NEXT_PUBLIC_API_URL`, `PUBLIC_WEB_URL` описаны в `.env.example`. После изменения публичного URL требуется пересборка фронтенда.
- Telegram — дополнительный канал: `TELEGRAM_BOT_TOKEN` и заранее подтверждённая запись `TelegramLink`. Без токена всё работает. Самостоятельная привязка Telegram через бота/вебхук не реализована. Сбой Telegram не отменяет бизнес-операцию; запрос ограничен пятью секундами.
- Нормативы ЕВСК не заданы в исходном задании. Есть расширяемая таблица `RankRequirement`; автоматическая проверка нормативов не выдумана. Текст юридически значимого согласия также должен предоставить оператор: MVP регистрирует факт уже полученного согласия.
- Публичные результаты и рейтинг обезличены; публикация персональных данных потребует отдельно определённого согласия.
- Общие UI-компоненты реализованы локально, без генератора shadcn/ui. Таблицы, формы и графики используют библиотеки указанного стека.
- В MVP нет самостоятельной регистрации и восстановления пароля по email, загрузки файлов в хранилище. Аккаунты создаёт федерация через интерфейс; пароль также меняет федерация.

Подробности: [архитектура](docs/architecture.md), [база данных](docs/database.md), [API](docs/api.md), [план реализации](docs/implementation-plan.md).

## Управление аккаунтами и редактирование соревнований

В кабинете федерации раздел **Учётные записи** позволяет создавать пользователей, искать по ФИО/email, фильтровать по роли и статусу, менять ФИО и email, назначать несколько ролей, блокировать/разблокировать вход и устанавливать новый пароль (от 10 символов, до 72 байт UTF-8). Пароли хешируются, не возвращаются через API и не записываются в аудит. При смене email, ролей, пароля или статуса все сессии пользователя отзываются. Нельзя отключить себя или последнего активного сотрудника федерации. Изменения фиксируются в журнале.

Для роли спортсмена выбирается профиль без аккаунта из реестра; сначала создайте его в разделе «Спортсмены», если его ещё нет. Профили тренера и судьи создаются автоматически. Снятие роли сохраняет профиль и спортивную историю. Повторное назначение роли использует сохранённый профиль.

В карточке соревнования кнопка **Редактировать** открывает все поля: название, дисциплина, тип, уровень, формат, возраст, даты проведения и заявок, место, описание, положение, календарный план и его номер, сезон и правило рейтинга. Время в форме локальное. Сервер проверяет даты и совместимость изменённых условий с активными заявками. Сохранение устаревшей версии отклоняется — обновите страницу и откройте форму заново. Изменение опубликованного протокола через карточку возвращает результаты в черновик и атомарно обновляет рейтинг; требуется повторная публикация протокола. Сама карточка соревнования остаётся опубликованной.

## Компактный режим запуска

`node_modules` не содержит исходники проекта: это восстановимые библиотеки. Анимации реализованы CSS без дополнительных зависимостей; неиспользуемая `class-variance-authority` удалена. Next.js уже оптимизирует импорты Lucide и Recharts.

После успешной сборки можно оставить только библиотеки запуска:

```powershell
npm run build
npm run compact
npm start
```

`compact` выполняет `npm install --omit=dev --omit=optional --ignore-scripts` и удаляет только кэши `node_modules/.cache` и `apps/web/.next/cache`. Готовая сборка и сгенерированный Prisma Client сохраняются. Необязательные бинарники SWC и Sharp исключаются: текущий интерфейс использует SVG и не требует серверной оптимизации изображений. Конфигурация Next.js в .mjs запускается без компилятора TypeScript. Команда не удаляет исходники, `.env` или БД. `npm start` запускает API на 4000 и собранный фронтенд на 3000; PostgreSQL должен работать. Для локального HTTP API использует настройки `.env`; на HTTPS-сервере задайте `NODE_ENV=production` и корректные URL.

Для возврата к разработке, миграциям и тестам:

```powershell
npm ci
npm run dev
```

Не удаляйте вручную отдельные папки библиотек: Next.js, Prisma и генераторы документов нужны для работы. При передаче исходников исключайте `node_modules`, `.next`, `dist` и `.env` (они уже перечислены в `.gitignore`).
